# 截图改版工作提示

输入：截图、页面与状态、用户任务、指定问题、可选拆解报告与约束。

请把截图中的体验问题变成可操作的改前/改后对比。按当前 SKILL.md 流程执行，用 templates/rationale.md 组织说明。

先区分：截图直接证明什么、报告推断什么、用户指定改什么。来自拆解的问题逐项引用报告标题、小节和条目，不能只写“根据之前的分析”。报告没测到的影响写为假设。

改前保持可识别的原布局、密度、内容与问题状态；不为了夸大差异把改前故意做坏。品牌标识换色块；被遮住的画面不要假装精确复原。多张状态用切换呈现，另注截图对应关系。

找出 3–5 项位置明确的问题，用“位置 → 事实 → 原则/影响 → 改法 → 指标 → 小实验”说明。用户已限定问题时，拆成有证据的具体表现，不扩大主题、不编新痛点。

改后提供真实可点的演示状态。隐私选择不得默认同意；引用必须支持对应主张，没依据时说清；会员权益按已核实规则显示，未知期限/折扣不能补造。模拟输出与真实服务分开，不调用额外模型。

输出 before.html、after.html、compare.html、rationale.md 和 compare.png。浏览器中实际验证而非只检查源码。用用户能理解的话说明变化、取舍与测试结果；“至少一半问题被认同”留给用户验收。
