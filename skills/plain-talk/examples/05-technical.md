# 技术方案：模型请求不自动重试

来源：[S5 · 技术方案](sources.md#s5--技术方案)。这是 M1 已实现的模型请求策略。

**输入原文：**

> 模型请求不自动重试，避免重复计费；日志不输出密钥、请求头、模型响应或底层异常正文。

## 老板版

模型请求失败后不会自动再发，目的是避免重试造成重复计费；日志也不输出密钥、请求头、模型响应或底层异常正文。原文没有提供实际节省的金额。

## HR / 外行版

像给按次收费的服务下单，没成功也不会自动再下一单，以免重复收费。工作记录里不写使用服务的“钥匙”、下单时附带的信息、服务返回的内容或程序出错时的详细原文。

## 研发版

模型请求不自动重试，以避免重试造成重复计费；日志不输出密钥、请求头、模型响应或底层异常正文。原文缺少失败类型、实际计费规则及日志过滤验证范围的口径，不能据此承诺所有失败请求都不收费。

## 核对

- 输入没有计费金额或次数，三版没有补入节省金额、请求上限或“失败免费”的承诺。
- “避免重复计费”保持为策略目的，未写成已测量收益。
- HR 版用日常词语对应四类不记录的内容，未将“不输出这些内容”扩大为“完全不留工作记录”。
- 只讨论模型请求，未推广到另有重试策略的 App Store 抓取。
