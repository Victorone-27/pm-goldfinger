# PRD 片段：整理服务失败时仍要出周报

来源：[S2 · 产品需求](sources.md#s2--产品需求)。输入属于任务书要求。

**输入原文：**

> 没有密钥或调用失败时，退化为只列原文，周报照样生成。

## 老板版

要求在没有密钥或服务调用失败时，仍生成包含原文的周报，让交付可以继续。原文未提供成本或工时影响数据。

## HR / 外行版

就像整理人员临时无法工作时，先把原稿交给读者：没有使用整理服务的“钥匙”，或服务没能正常回应时，周报仍要生成，只放原文。

## 研发版

要求在密钥缺失或调用失败时，跳过解读并只列原文，仍生成周报。缺少调用失败的判定范围、超时阈值和输出验收口径，不能据此认定失败路径已实现。

## 核对

- 原文没有数值，三版未补入重试次数、超时秒数或收益数据。
- 两个触发条件和“仍生成、只列原文”均保留。
- 三版保持需求身份；HR 版用“仍要”，未将要求改成已经实现的结果。
