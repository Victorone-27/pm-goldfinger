# 老板版复核与修改

来源：用户在 M6 验收后明确要求“老板版先给结论，不能只是复述原文”。本轮使用 plain-talk 规则逐份检查五个示例；只修订老板版表达及相关规则，不修改原始输入、来源、HR 版、研发版与数字核对。

| 示例 | 原先的问题 | 现在先说什么 | 保留的边界 |
| --- | --- | --- | --- |
| [互联网黑话周报](../../skills/plain-talk/examples/01-weekly.md) | 先讲运营动作，再报指标 | 本周主要流程的转化表现更好了 | 3 个百分点；没有推导收入 |
| [PRD 片段](../../skills/plain-talk/examples/02-prd.md) | 开头直接罗列功能和限制 | 让用户按条件拿到一份订单清单 | 仍是待实现需求；1000 条上限、筛选、字段和空结果行为不变 |
| [用户简历](../../skills/plain-talk/examples/03-resume.md) | 直接复述指标及交付周期 | 试点答得更准，信息收回比例提高；历史测算显示视频可更快交付 | 200 题题库、50 名销售试点、75%→94%、50%、5–7 天→2–4 天及“按历史任务测算”不变 |
| [常见指标](../../skills/plain-talk/examples/04-metric.md) | 只是展开缩写并复述两个指标 | 用户变多，第二天回来的比例也更高 | 12%、35%→41%；比例增加不偷换为回访总人数增加 |
| [技术方案](../../skills/plain-talk/examples/05-technical.md) | 已解释机制，但可以更先讲用途 | 回答要依据保险条款 | 保持方案身份；没有承诺一定答对、一定有引用或一定省钱 |

指标示例当前老板版：

> 用户在变多，第二天回来的比例也更高了：日活比上一统计期涨了 12%，第二天还会回来的人占比从 35% 提升到 41%。

与用户建议的方向一致，并把“留下来的也更多”明确为“比例更高”，避免由留存率直接推断绝对人数。

同步更新 `SKILL.md` 与 `prompts/rewrite.md`，将“先给结论”落实为先概括有依据的变化、用途或决定，再给数字或做法。`docs/demos/plain-talk.html`、`tool-plain-talk.png`、README 首屏预览和作品集网页 / 长图使用同一版内容。

验证：逐例检查结论受到原文支持；老板版不超过三句；与 M6 提交逐段对照，输入、来源及其他版本未改，原有数值均保留。未添加独立模型调用或改变自然语言触发方式。
